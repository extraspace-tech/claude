# Model routing (v2, ported 2026-10-13 from Porsche-AI; Fable not available here)

Always loaded (no `paths:` filter). This workspace runs with `CLAUDE_CONFIG_DIR=~/.claude-extraspace`, so "global" below means `~/.claude-extraspace/`, not `~/.claude/`.

- **Main session = Opus 5.5, high effort = architect and software engineer.** Explores, designs, writes plans and briefs, splits the work, briefs the subagents, reviews what they return, reports a verdict. It does not write or patch product code itself, not even a small fix. Memory, plan, spec and rule files are its own to write. `.claude/settings.json` sets `"model": "opus"`; effort comes from `~/.claude-extraspace/settings.json` `effortLevel: high` (Opus 5.5 defaults to medium, so the setting matters). The global `CLAUDE.md` rule says the main session should be Fable and to say so once if not: in this workspace Opus 5.5 is the intended main model, so do not report it.
- **Implementation → `implementer` subagent** (`~/.claude-extraspace/agents/implementer.md`, Opus 5.5, high, all tools). The brief names the repo (`../CMS`), the csproj (`src/ExtraSpace.Api/ExtraSpace.Api.csproj`, tests under `tests/`), the files the agent owns, the shared contracts, the spec feature doc, `docs/notes/cms/built-so-far.md` and the shared notes file in the session scratchpad. Money, concurrency and payment work still gets exact code in the brief or plan.
- **Code review → `code-reviewer` subagent** (`.claude/agents/code-reviewer.md`, Opus 5.5, high, read-only tools + `mcp__postgres-local__execute_sql`, `mcp__postgres-staging__execute_sql`). Covers `/code-review` and superpowers spec-compliance / code-quality steps. Its report is input to the main session's own review, not a replacement.
- **Live walk → `dev-walker` subagent** (`.claude/agents/dev-walker.md`, Sonnet 5.5, medium, tools Bash / Read / Grep / Glob + the two Postgres MCP tools). Never Haiku: a walk writes to a live database through the API (local Docker today, staging later). First Sonnet walks: GET-only cases first; revert to `opus` if a walk leaves rows behind or misreads a PASS. Parallel walkers share ONE local app (memory `feedback-parallel-walkers`).
- **Code locate / "where is X" → project `Explore` agent** (`.claude/agents/explore.md`, Haiku 5.5, low, read-only). It overrides the built-in Explore, which would otherwise inherit the main model.
- **Research / reading → `general-purpose` with `model: "sonnet"`.** Pass `model: "opus"` only where judgment is the task. `Plan` agent is not used; plans stay in the main session.
- **Parallel work.** Several subagents at once when the pieces are independent. Each owns its own files; two never edit the same file. Dependent work waits. The main session is the hub: each brief names the other running subagents, their files, the shared contracts, and one shared notes file in the scratchpad; changes between agents go through the main session (SendMessage). A subagent that finds a conflict stops and reports.
- **After the subagents finish** the main session reads the real diff (`git -C ../CMS diff --stat`, then the hunks of the risky files; the full diff only for money, concurrency or shared-table code) and the build / walk output, checks the pieces fit, sends defects back to an implementer, and reports ACCEPT / FIX NEEDED / BLOCKED per piece with what was verified and what was not.
- **Briefs and reports.** Briefs point to files, never paste them. Reports come back as a table plus at most 15 lines.
- **Session hygiene.** One task per session. `/rename` then `/clear` between tasks. `/compact` only at a boundary after the plan or state is in a file, never mid-implementation. A `UserPromptSubmit` hook (`.claude/hooks/compact-nudge.py`) prints one line when the main context passes 150k tokens, then every 50k more.
- **Fallback:** agent files load at session start. If an agent is "not found", dispatch `general-purpose` with the matching `model` and paste the agent body at the top of the prompt.
- Quick checks that decide the next step (one grep, one query) stay in the main session.
- Unchanged house rules: design gate (present the design, wait for go-ahead before code), no commit or push unless asked in that turn, migrations by hand, no SQL writes, and the 🔴 production DB hard rule (`.claude/CLAUDE.md` §6): never write to production, never run a walk on it, a production change is a script the owner runs by hand.
- Cursor: the hybrid workflow (`.cursor/rules/implementer.mdc`, `docs/plans/TEMPLATE*.md`, `.claude/scripts/`) stays for the times the user chooses Cursor; it is not the default.
