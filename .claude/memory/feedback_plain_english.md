**Write in plain, simple English.** The user said (2026-07-15): "use simple english pls. Sometimes I am having a hard time understanding what you are saying."

**Why:** English is not the user's first language. Long sentences, stacked clauses and figurative shorthand cost them re-reads. This is about readability, not length: full detail and thorough analysis stay.

**How to apply:**
- Short sentences. One idea each.
- Say the plain word. Avoid figurative jargon ("load-bearing", "blast radius", "escape hatch", "greenfield").
- Spell out any term the first time.
- Keep tables, headings, ✅/❌ markers and code blocks; simplify the prose.
- Applies to chat replies, commit messages and BA / client drafts (paste-ready, user's voice, numbered questions, no file paths or class names in client-facing text).

Does NOT mean: dumb it down, skip detail, or drop technical precision. Table names, method names and line numbers stay exact. Related: [[feedback-comment-style]].
